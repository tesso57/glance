# glance モデル化ベンチマーク

Go、TypeScript、Java の合成コードを対象に、状態・遷移・性質をどの程度正確にモデル化できるかを評価するための固定ケースです。実際のユーザーコードは含みません。これは実行速度の測定ではなく、モデルの内容と根拠の評価です。

| サイズ | Go | TypeScript | Java | 評価の中心 |
| --- | --- | --- | --- | --- |
| small | `small-go` | `small-ts` | `small-java` | 一つの操作の成功・失敗と入力の前提 |
| medium | `medium-go` | `medium-ts` | `medium-java` | 外部状態の途中失敗、非同期・共有状態 |
| large | `large-go` | `large-ts` | `large-java` | 複数ファイル、依存先の具体的な振る舞い、失敗後の再試行 |

各ケースの `input/` は分析対象、`request.md` はエージェントへの依頼、`expected.md` は評価者用の期待事項です。期待事項はコードに基づいた評価の補助であり、これ自体が正しさの形式証明ではありません。ケースの変更は比較結果を変えるので、結果には Git のコミットまたはケースの内容ハッシュを記録してください。

## 実行準備

リポジトリのルートから、新しい作業ディレクトリを指定します。指定先が既にある場合は上書きせず失敗します。

```sh
node benchmarks/prepare.mjs medium-go /tmp/glance-bench-medium-go
cd /tmp/glance-bench-medium-go
pi -e /path/to/glance/extensions/index.ts
```

Pi で `/glance REQUEST.md の依頼を実行してください` と入力します。準備スクリプトは `input/` と依頼文 `REQUEST.md` のみをコピーし、`expected.md` はコピーしません。これは評価時の答えの混入を避けるための準備であり、ファイルアクセスを隔離するサンドボックスではありません。モデル作成中は元の `benchmarks/cases/` や評価結果を読ませないでください。

各実行で新しい作業ディレクトリと Pi セッションを使い、モデル・thinking・Pi / glance / TLC バージョン、実行日時、対象ケース、試行番号を記録します。固定 TLC を用意して `/glance check` や `/glance chart` を実行した場合は、その結果と設定を記録します。既存 `.glance/` の再利用、対話履歴の混入、モデルの変更は結果に影響します。

## 評価

モデル作成が終わってから対応する `expected.md` を読み、生成された `.glance/` の資料、TLA+、図と照合します。各観点を「確認できた」「欠落・誤り」「対象外と明記」「未確認」で記録し、根拠となるコード・生成物の位置を残します。

- 状態と遷移、成功・失敗時の結果と副作用を正しく表しているか。
- コードの事実、モデルの仮定、未確認事項を分け、重要な条件や失敗を見落としていないか。
- 保証する性質が妥当か。TLC が完了したか、違反や構文・実行エラーがあるか。
- 図・用語説明がモデルを誤解なく示すか。集約や省略、根拠を確認できるか。

TLC の成功は生成モデルの設定内の結果であり、元のコードとの一致や期待事項の網羅性を自動で保証しません。エージェントが生成した資料と検査結果は別々に記録します。一回の出力だけで安定性を判断せず、同条件の複数試行を比べてください。
