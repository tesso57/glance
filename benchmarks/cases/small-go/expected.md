# 評価用の期待事項：small-go

このファイルは評価者向けであり、モデル作成時にはエージェントに渡さない。

## 対象と前提

- `input/task.go` の `Complete` を単一呼び出しとして扱う。外部の同時更新はないと仮定する場合、その前提を明記する。
- `Status` は文字列を基底型とするため、定数以外の値も取りうる。非 `InProgress` を一つにまとめてもよいが、その意味を明記する。

## 必須の振る舞い

| 操作前 | 戻り値 | 操作後 |
|---|---|---|
| `task == nil` | `false`、非 nil の error | Task の変更はない |
| 非 nil、`Status == InProgress` | `true`、nil error | `Status == Done` |
| 非 nil、`Status != InProgress` | `false`、nil error | `Status` は変更されない |

- 成功時に `Done`、非 nil のタスクに対する失敗時は元の `Status` を保証できる。
- `Done` への再呼び出しは `true` ではなく `false, nil` を返す。nil の場合に panic が起きるという記述は誤り。
- モデルから nil、任意文字列、並行性を省くならその範囲を明示する。実装とモデルが一致していることを TLC だけで証明したと報告しない。

## 評価観点

コードから分かる三つの結果と副作用を混同せず、モデルに含む範囲と根拠を説明しているか。生成された TLA+ は、有限の TLC 設定により構文・不変条件の検査が行えるか。到達不能な状態に関する主張や未実施の検査を成功として報告していないか。
